## 浏览器检查

在逐对象模式下拦截实际 WebGL 调用，500 对象用例的两边每帧都是 500 次普通绘制、0 次实例化调用。正式报告还会核对双方每个样本的可见数和三角形数。

像素比较使用 RGB 平均绝对误差，阈值为 3/255。覆盖街区、仓库和机械阵列，以及普通 Mesh、InstancedMesh 两种对照。

布局检查覆盖 532×863、390×844、1024×640、1280×720、1440×900，确认控件、双画布和完整结果不溢出，测试前后画布尺寸保持一致。另有 20,000 对象场景的重建与释放检查。

上下文恢复使用 `WEBGL_lose_context` 主动注入故障。恢复后会重新检查像素，并完成一次新的性能测试。

镜像回归使用 256×256 画布和四个单面三角形。修复前，混合正负缩放的 Rust 逐对象路径只得到 4,710 个着色像素，普通 Three.js Mesh 为 9,419 个，RGB 平均误差为 9.02/255。修复后两条 Rust 路径及 Three.js 实例化适配器均与普通 Mesh 对齐；从背面观察时着色像素为零。用例还检查缩放符号变化后的批次迁移，混合朝向为两次实例化绘制，统一朝向为一次。

非原点用例将三角形放在局部 x≈10 处，使用球心 `(10, 0, 0)`、半径 0.75。仅提供该半径、保持原点球心时，Rust 剔除后没有着色像素；正确球心下与关闭剔除的参考画面一致，为 2,730 个着色像素。相机移动后可见对象由 2 个变为 1 个。逐对象、实例化和上下文恢复均检查画面与可见数，另用 500 个包围球、三个视角做真实 WASM 与 Three.js 差分测试。

剪切回归用非均匀父缩放 `(1.000008, 1, 1)` 和子节点 45° 旋转。单位球中心位于 x≈2.000006 时，球面有一点落在 x≈0.999998，已进入右裁剪面 x=1。原最大列长度约 1.000004，会错误剔除整个对象；新的保守上界保留它。浏览器用放大的边缘三角形检查实际像素，两种 Rust 路径开启与关闭剔除的画面完全一致。

剪切用例不把 Three.js 原生包围球算法作为正确性依据：该路径也会漏掉上述对象。标准场景仍逐样本检查两边工作量，自定义剪切场景须关闭剔除，或接受报告因工作量不同而终止。

溢出回归将父子缩放都设为 1e20。修复前，世界矩阵出现三个非有限值，关闭剔除后队列仍接受一个可见对象及 16 个矩阵元素；旧队列也继续报告可见。现在更新明确报错，队列失效且不能重新准备。浏览器拦截清屏、矩阵上传及 draw 调用，逐对象、实例化和旧 RustRenderer 在这些错误路径上均为零次提交；修正变换并重新准备后，像素与错误发生前完全一致。

光照回归使用斜面 z=x。修复前，沿 z 平移 1e8 后，Rust 与 Three.js 共享 shader 都将斜面算成近似水平面，中心像素为 `[171, 76, 38]`，红色通道比解析结果 114 高出 57。修复后，两种绘制策略在原点和 ±1e8 平移下均与解析结果对齐，每通道误差不超过 2/255；同时检查极端缩放、镜像、unlit 及旧实验页。该用例验证光照稳定性，不证明大坐标下的投影或深度精度。

GPU 样本完整性用例模拟每四次查询分配失败一次。修复前，72/96 个返回值仍被标为 `available` 并计算中位数；现在该侧标为 `incomplete`，页面显示“采样不全”，JSON 中位数为 null，保留 72 个原始结果和预期数量 96。另一侧完整的 96 个结果仍可显示中位数。逐对象与实例化两种对照均验证完整及缺失两种情况。模拟扩展只用于验证采样流程，不代表实际 GPU 性能。

GPU 诊断用例在两种绘制策略下分别模拟正常、分配失败、非法时长、结果不返回、扩展缺失和 disjoint。每四次失败一次时，报告分别记录 24 次分配失败或 24 个无效结果；始终不返回时，四轮合计跳过 64 帧、释放前有 32 个未返回查询。扩展缺失和 disjoint 分别记录 4 轮，另一组保持完整的 96 个样本。Node 用例还确认诊断快照独立、迟到结果可正常排空，读取统计不触发结果读取，未返回查询在 dispose 时全部释放。

矩阵抵消用例将父节点旋转 45° 并沿 x 缩放 1e8，再用平移抵消子节点的 x 偏移。原实现把子节点剩余的世界位移 `[-0.35355338, 0.35355341, 0]` 算成 `[0, 0, 0]`；修复后脏更新与全量更新都保留该偏移。浏览器将层级场景与直接设置解析位置的平面场景比较，两种绘制路径的 RGB 平均误差均小于 0.05/255。另检查 1e20、1e30 乘积相消得到有限结果，以及真实溢出的明确拒绝。

点投影回归中，原实现对 `1e-30 × I` 和点 `[1, 2, 3]` 报“w 为零”，对 `1e30 × I` 和约 `[1e20, 2e20, 0]` 返回 Infinity；修复后都返回对应的有限输入点。另以 Three.js 对照透视矩阵的正负缩放，检查分母相消、零 w、最终溢出和输入不变。浏览器将投影后的三角形与解析顶点直接绘制的画面比较，逐对象和实例化两条路径像素完全一致。

材质更新用两个三角形共享同一材质。检查颜色同步变化、lit/unlit 切换及原始参数不被回写；连续 64 次更新期间拦截 GPU 对象创建，两种路径均没有新增 program、buffer 或 VAO。随后主动丢失并恢复上下文，验证保留已更新颜色，再在第二次丢失期间修改材质，恢复后显示新颜色。底层 Rust 接口另检查无效 ID、长度、NaN 和越界值不会覆盖原材质；TS 同时检查稀疏数组与 dispose 后调用。

几何更新用红、绿两个对象在不同材质组引用同一几何体，另有独立的蓝色标记。顶点从视锥外移入后，两组一起变为可见；独立组的包围体与像素保留。连续 64 次更新没有新增 program、buffer 或 VAO；退化为点的三角形不产生像素，恢复顶点后可继续绘制。两次上下文丢失分别检查既有更新和丢失期间更新，外部顶点、索引及批次数组修改不会改变恢复结果。包围球单测还覆盖 f32 球心舍入、半径向外舍入和半径溢出拒绝。

拓扑替换将同一共享几何从视锥外的三角形换成视锥内的四边形，可见对象由 1 个变为 3 个、三角形由 1 个变为 5 个。32 次交替扩容/缩容后存活 GPU 对象数保持不变，未重建 program；最终 dispose 后对象全部释放。分别注入 VAO、顶点句柄、索引句柄、顶点存储和索引存储分配失败，原画面、三角形数与存活资源均保持不变。上下文恢复与丢失期间替换另做像素和统计检查。故障注入验证清理逻辑，不等同于真实驱动显存耗尽测试。

初始缓冲分配用例让 bufferData 不建立存储，保留真实缓冲句柄。修复前，实例化 EngineRenderer 在请求 64 字节、实际为零时仍返回成功；修复后明确拒绝，缓冲和 program 句柄计数回到零。旧 RustRenderer 依次注入顶点、索引、实例矩阵和颜色存储失败，均清理全部资源，恢复正常分配后可再次创建并绘制。另检查零实例容量以及上下文恢复期间的同类失败：状态为 failed，后续绘制调用数为零。

重建失败回归连续两次阻止恢复期间的缓冲分配，第三次恢复前解除故障。原实现停留在 failed，忽略后续上下文周期，页面也永久停用；现在两种绘制路径都可恢复，像素哈希、相机和暂停状态与故障前一致。失败期间绘制为零，等待四帧不增加分配次数；重复恢复事件不触发重试，每次真实丢失只增加一次 generation。该测试覆盖瞬时资源失败后的恢复，不保证浏览器一定会再次提供可用上下文。

恢复回调重入用例覆盖四种情况：回调内 dispose、dispose 后抛错、同步再次派发恢复事件、重入后抛错。修复前，前两种会把 disposed 改为 ready 或 failed，后两种会在同一轮执行两次重建；修复后终止状态保留，重建每轮只执行一次。Node 与真实 WebGL 丢失/恢复事件均验证状态、通知序列、代次和后续恢复；额外恢复事件由用例同步注入，不代表浏览器必然产生这类事件。

相机矩阵乘法回归构造 `1e8 + 0.5 - 1e8` 的视图偏移，原 TS helper 输出 0，修复后保留 0.5；另检查 1e20、1e30 中间乘积相消和真实溢出。轨道相机在距离 7.4、yaw 0.34、pitch 0.45、target `[3, 7, -11]`、宽高比 1.6 时，原组合矩阵第 14 项为 1.80809485912323，修复后为与 Three.js 一致的 1.8080949783325195。浏览器将抵消用例与独立计算的参考矩阵绘制结果比较，逐对象与实例化两条路径均保留正确偏移和画面；该用例验证 CPU 矩阵组合，不证明 GPU 大坐标计算精度。

高斯支持范围测试在 256×192 的 WebGL2 画布中绘制 28 个合成高斯，比较统一最坏范围与按不透明度收紧的范围。两边使用相同片元求值、阈值、混合和顺序，RGBA 不同通道数为零；提交四边形总面积从 15,110.25 降到 5,877.31 像素²。独立边界用例保留 alpha 恰好等于阈值的中心像素。Node 另用 Cholesky 参数化检查 108 组椭圆的阈值边界和稳定索引压缩，Rust 覆盖极端方差和非法批次。面积变化不能替代 GPU 时间、真实模型画质或跨设备测量；复现命令与论文链接见[高斯光栅化准备](gaussian-rendering.md)。

高斯屏幕滤波以 4,097 项正定 f32 协方差对照 `Σ′ = Σ + εI` 和行列式补偿；零方差滤波按位保留输入，超出 f32 的输出与无效整批都会拒绝。浏览器将单项 `[16, 5, 9]`、`α=0.7`、`ε=0.6` 光栅到 512×512 画布，滤波前后 alpha 字节和分别为 12,166 与 12,152，解析连续积分相对差小于 `2e-6`。这是单高斯屏幕空间数值和像素回归，不代表重叠 alpha 合成、真实场景的 PSNR/SSIM 或帧率结果。

高斯半空间裁切以 4,097 项正定协方差对照独立条件高斯公式，并检查法线与偏移等比例缩放、零法线和无效整批。浏览器在 256×192 WebGL2 画布以斜平面裁切一个高斯：左、右 alpha 分别为 15、0，中心片元按实际半像素偏移得到 0.4723179 的 CDF 因子，1,166 个像素可见。它验证局部仿射 EWA 的系数与片元方向，不证明完整场景近裁剪、交叠混合、PSNR/SSIM 或性能。

高斯训练 PLY 回归使用字段乱序的二进制小端输入，检查中心、log-scale 与 `[w, x, y, z]` 旋转激活后的协方差、sigmoid 不透明度、0 阶 SH 线性 RGB 及连续 1 阶 `f_rest_*` 系数。Rust 额外验证 1 阶方向项、3 阶末项、世界相机位置的逆仿射变换、非法系数和相机重合拒绝，以及单位与 90° 旋转的解析协方差、极小非零四元数归一化和零四元数、非有限或溢出的尺度拒绝。Node 将一次 Three.js 紧凑视图准备与分步模型空间 SH、相机空间变换和筛选结果逐项比较；浏览器由同一入口完成世界到模型相机位置、SH 颜色、准备与上传，并验证远近记录的动态颜色保持。测试不读取真实模型文件或纹理，也不代表模型加载耗时、画质或帧率。

高斯相机空间变换以一个带旋转、非均匀缩放和平移的列主序仿射矩阵，核对中心和六分量协方差的解析结果；另检查恒等变换、透视项、奇异线性部分、非有限中心和非正定协方差。Rust 直接检查单次 Three 相机组合的 z 翻转、投影/奇异/长度拒绝；Node 将 Three.js 的 `model.matrixWorld`、`camera.matrixWorldInverse` 与 z 翻转参考逐项比较，并确认模型原点位于正 z 前方。PLY Node 用例验证转换后的数组与原始不透明度、颜色数组互不共享；浏览器将同一 Three 约定的组合结果送入准备和上传，检查两个中心深度和远近颜色。该回归验证仿射数据衔接，不代表自动监听 Three.js 相机动画或模型性能。

高斯视图准备以四项输入覆盖跨近平面、可见、跨远平面和离屏候选，检查输出源 ID `[2, 1, 0]`、远到近深度、滤波后属性、线性 RGB 与局部瓦片引用对齐和输入不变。浏览器将准备输出直接送入含 CDF 的片元路径，16 像素瓦片产生 52 条局部引用，裁切相对未裁切有 23,264 个不同通道。该回归验证数据衔接，不代表主渲染器、真实模型性能或画质。

高斯上传打包检查每项 15 个 f32 的中心、范围、逆协方差、不透明度、裁切状态与 RGB，拒绝非正定协方差、负颜色、畸形瓦片偏移与溢出 f32 的逆矩阵。浏览器把三项记录上传到 180 字节 VBO，以一次实例化绘制读取所有属性；瓦片缓冲为 980 字节，裁切相对未裁切有 23,264 个不同通道，且无 WebGL 错误。该回归只验证属性布局和上传，不等同于完整渲染器资源生命周期或性能测量。

高斯上传缓冲在模拟 WebGL 中检查内部副本、资源快照、容量内子更新、瓦片缓冲释放、主动卸载和静默分配失败后的清理/重试；真实浏览器覆盖三项上传、两项缩减、`WEBGL_lose_context`、恢复前更新及恢复后的 VBO 读取。快照将记录、源 ID、瓦片副本与可用 VBO 容量分开统计；丢失和分配失败时 GPU 数值归零，恢复后与重传数据一致。卸载后快照、瓦片布局和记录数均为空，恢复不重传旧视图，后续上传会重新建立缓冲；绘制器卸载后拒绝 draw，重新上传后像素与卸载前一致。该回归不包含 VAO/shader 卸载、恢复耗时、驱动开销或显存测量。

高斯光栅 pass 在真实 WebGL2 中读取三项交错记录，以预乘线性 RGB alpha 合成 CDF 裁切结果。裁切相对未裁切有 23,264 个不同通道；上下文恢复前后裁切图逐字节相同，且调用前设置的混合状态会恢复。另以红、青两项记录核对中心像素颜色分量。该回归不调度瓦片、不读取 SH，也不代表真实模型性能、完整透明度处理、画质或资源成本。

`gaussian-blending.spec.ts` 分别检查全屏和瓦片路径：五组独立 RGB/alpha 方程覆盖减法、反向减法及 MIN/MAX，合成像素必须与标准加法逐字节相同；红绿两个半透明高斯的中心值与解析预乘 RGBA 对照。调用前混合开关、独立因子和方程在正常返回或注入绘制异常后均保持，异常后的重试输出不变。JSON 报告记录不同通道数和前后状态；此项只验证混合状态，不覆盖深度/剔除策略或性能。

高斯瓦片绘制检查上传缓冲只给出瓦片元数据与局部 ID，调用方无法改写内部引用数组。真实 WebGL2 中 52 条 16 像素瓦片引用以 scissor 提交，输出与全屏紧凑路径逐字节相同；连续局部 ID 合并为一条实例化提交，浏览器回归确认调用数小于引用数。逆序 ID 在 Node 回归中保持拆段和原顺序；调用前关闭 scissor 并设置非默认盒子，返回后状态保持。该回归只验证提交语义，不推断速度、GPU 时间或端到端性能。

高斯瓦片分箱与瓦片内排序用独立 JavaScript 行优先、稳定排序参考核对 4,097 个有限屏幕范围和深度，包含离屏、边界相交、偏移格式、同深度及跨瓦片复用。256×192 WebGL 用例中，8 个重叠候选生成 23 条瓦片引用；稳定瓦片顺序与逐项全屏远到近绘制逐通道一致，均有 1,124 个可见像素。故意使用未排序瓦片列表会产生 1,651 个不同通道。该回归只验证候选覆盖和混合顺序：瓦片路径提交更多四边形，不用于推断 GPU 时间或帧率。

高斯深度排序用 Rust 比较排序和 JS 稳定排序作独立参考，检查完整 f32 范围、相邻值、正负零以及候选输入顺序。WASM 回归覆盖 65,537 个深度的压缩候选和返回副本；非法深度、越界及重复索引不返回结果。两个重叠高斯的 WebGL 用例分别验证远近排序与正负零同深度的稳定排序，输出与参考顺序逐像素一致，中心 RGBA 与解析值相差不超过 1/255。该测试验证排序与混合正确性，不证明真实模型帧率、逐像素遮挡或相机运动中的完整画质。

资源统计回归拦截 WebGL 创建、删除和存储分配，在每次分配后读取真实 `BUFFER_SIZE`，与 SDK 快照逐项核对。两种路径覆盖 16 次拓扑扩缩容、失败回滚、材质/顶点原地更新，以及丢失期间修改和重建失败后的恢复。100 对象的实例矩阵容量为 6,400 字节，逐对象模式为零；未收到丢失事件时也不报告已失效缓冲。CPU 快照逐项核对 Engine 自身顶点、索引、批次和动画 TypedArray 的 `byteLength`：替换后同步变化，丢失、失败和恢复期间不变，dispose 后归零；构造对象不保留完整输入场景属性。两类统计都不触发 `getBufferParameter`，dispose 后 GPU 存活对象与计数均为零。底层快照另验证零字节缓冲仍计为一个对象，且渲染器释放后快照仍可读取并单独释放。

世界 AABB 用 512 个带层级、镜像、剪切和零缩放的节点，与 Three.js `Box3.applyMatrix4` 的角点范围比较，要求结果包含参考范围。另将 f32 值转为 2^-149 单位的 BigInt，对 42 组极端量级组合精确计算八个角点，验证包含关系或溢出拒绝。Rust 覆盖大数抵消、次正规数、f32 最大端点、输入校验、失效场景和整批溢出。浏览器两种绘制路径检查旋转/剪切盒的实际像素落在查询范围内、平移后范围更新、与 Three.js 画面一致，以及查询不改变 GPU 资源数量；像素边缘允许一个像素的抗锯齿余量。

射线候选用 512 个盒、两组起点和四个方向，与 Three.js `Ray.intersectBox` 比较命中及边界参数；另以 BigInt 有理数检查 72 组极端坐标/方向组合，确认进入、离开区间包含精确交点。Rust 覆盖正/负零平行轴、盒内起点、相切、零尺寸盒、范围裁剪、方向缩放和非法批次。浏览器将前后遮挡盒按非距离顺序提交，两条渲染路径均能通过进入参数选出与可见像素一致的盒；移动前方盒后，重新查询命中后方盒，旧快照保留旧候选，GPU 资源数量不变。

四元数回归中，原实现将 `[0, 0, 0, 2^-149]` 拒绝为零长度，虽然它表示单位旋转；现在可正确归一化。Rust 覆盖最小正 f32、最大有限值以及可精确表示的正负倍数缩放。Node 对 36 组输入比较 Three.js 归一化与矩阵合成，检查场景构造及变换更新；混入全零、NaN 或 Infinity 的批次不修改原矩阵和已准备的队列。浏览器用含镜像的父子场景对比正常量级输入，极小四元数构造、连续编辑、无效批次及上下文恢复后的两条路径均保持相同画面与资源数量。

三角形求交用 256 个含正反绕序的三角形、三个方向及两种剔除设置，与 Three.js 比较命中参数和重心坐标，并按权重重建交点。另检查 25 组顶点/方向尺度组合、边界接触、范围裁剪、共享边、无效索引和返回副本。浏览器在两条绘制路径中验证：包围盒命中但三角形空白角落不命中；按非距离顺序提交的前后表面可选出可见交点；更新前方顶点后命中后方表面，颜色与像素一致，GPU 资源数量不变。这些用例不证明任意近退化或共享边输入都具备 watertight 性质。
