# 实现笔记

场景更新、渲染队列和绘制提交各自独立。Rust 引擎路径不调用 Three.js；对照组单独放在 `web/compare/`。0.3 新增逐对象绘制，作为默认性能对照。

## 一帧经过哪些步骤

1. TS 传入绝对动画时间，Rust 更新选定节点的局部四元数。
2. `SceneGraph` 按父节点先于子节点的顺序更新世界矩阵。逐对象对照强制全量重算，实例化对照使用脏标记。
3. `RenderQueue` 提取相机六个平面，对几何体包围球做测试。
4. 逐对象模式保留节点描述顺序；实例化模式再按几何、材质和世界矩阵朝向打包矩阵。
5. 逐对象模式用 modelMatrix uniform 加 drawElements；实例化模式上传矩阵 buffer 并调用 drawElementsInstanced。

光栅化和像素着色在 GPU 上执行。Rust 不逐像素画图。

## 场景图

每个节点保存父索引、10 个 f32 的局部 TRS 和 16 个 f32 的世界矩阵。构造和改父节点时生成拓扑顺序；改父节点先验证副本，拒绝循环后再写回。

四元数长度在 f64 中计算，除以长度后写回 f32。有限 f32 分量的平方和在 f64 中既不会上溢，也不会因非零次正规数而下溢，因此只拒绝真正的零长度，不使用绝对大小阈值。`compose_transform()`、场景构造和两种变换更新接口共用此规则；批量更新先校验并归一化全部输入，失败时保留原变换及队列版本。

世界矩阵相乘时，每个元素的四项乘积与累加使用 f64，完成后才舍入到 f32。原来的 f32 逐项累加可能把 `1e8 + 0.5 - 1e8` 算成零，也可能在最终结果有限时先产生 Infinity 再得到 NaN。单矩阵、批量矩阵和场景层级共用该实现；公开乘法接口会拒绝最终超出 f32 范围的结果。局部矩阵合成和每层存储仍使用 f32，GPU 投影精度不在此改动范围内。

独立的 `transform_points()` 同样使用 f64 乘加，并在齐次除法完成后才写回 f32。它允许非零的小 w 和负 w，拒绝零 w 与最终输出溢出；因此等价的齐次矩阵整体缩放不会仅因绝对阈值而失败。它是 CPU 数学接口，不替代 shader 的顶点投影，也不执行视锥裁剪。

脏标记分为节点自身变化和本轮世界矩阵变化。更新时：

```text
worldChanged[id] = localDirty[id] || worldChanged[parent]
```

没有变化的节点不做矩阵乘法，但仍会遍历索引，因此更新遍历是 O(N)，不是 O(脏节点数)。`updated_count()` 记录实际重算的矩阵数。`update_all_world_matrices()` 专门用于强制全量计算和旧的 CPU 基准。

每个重算后的世界矩阵都检查有限性。局部 TRS 合法并不保证层级乘积能用 f32 表示，例如父子各缩放 1e20 时会溢出。构造和矩阵更新会返回包含节点编号的错误，JS 接口对应抛出异常。更新不会回滚已计算的矩阵，而是将整个场景标为不可绘制；修正变换或父子关系后重新更新，直到所有无效节点恢复。静态无效节点也会保留错误状态，不能靠一次空更新清除。

场景另有一个共享的版本与就绪标记。成功修改 TRS、动画或父节点时使矩阵失效；每次世界矩阵更新都会推进版本。渲染队列只保留这个小标记和准备时的版本，不持有场景矩阵。旧队列、未更新的场景以及释放后的场景都会被渲染入口拒绝；逐对象路径还检查队列是否属于传入的同一个场景。失效队列的可见数、批次数与有效矩阵长度均为零。

`animate_nodes(ids, seconds)` 是演示动画接口：覆盖指定节点的局部 Y 轴旋转，不是动画混合系统。业务可以使用 `set_transform()` / `set_transforms()` 自己设置 TRS。

## 可见性与分组

`RenderQueue` 的构造输入为可绘制节点索引、组索引、局部包围球半径和组数，默认球心为原点。每个组对应一个几何体/材质组合，组的映射由 TS 场景构造器生成。每帧在 Rust 中完成计数、偏移计算和矩阵压紧。

`set_bounds(centers, radii)` 可替换全部局部包围球；球心按可绘制节点顺序存储，每个球心三个 f32。成功后清空可见列表并使队列失效，必须重新 prepare 才能绘制；长度错误、非有限坐标或负半径会被拒绝，原包围球和队列不变。零半径表示点包围体。`EngineScene.centers` 对应这个可选输入，省略时保持原点球心。

球心乘以完整世界矩阵，因此跟随父节点、旋转、缩放和镜像。输入球体必须覆盖局部顶点。半径按世界矩阵线性部分 A 的最大拉伸上界放大：计算 AᵀA，取其最大绝对行和与迹的较小值，再开平方。两者都不小于最大特征值；正交变换退化为最大列长度，剪切则包含非对角项，不使用忽略微小剪切的阈值。

视锥平面提取、球心转换和半径计算使用 f64 中间值，矩阵存储及 GPU 上传仍为 f32。半径上界留出 8 个 f64 epsilon 的相对舍入余量。这样可避免有限 f32 缩放的平方上溢或下溢，也不会把仅乘了一个很小正数的投影矩阵误判为退化；法线长度为零的平面仍会被拒绝。已经上溢的世界矩阵由场景更新拒绝，不会进入剔除或绘制。

Three.js 对照保留原生 Sphere.applyMatrix4 的最大列长度算法。该算法在剪切下可能缩小包围球，因此剪切正确性测试以实际进入视锥的点、解析拉伸值及关闭剔除的画面为依据。标准场景没有剪切；自定义剪切场景若出现可见数差异，性能报告会拒绝输出，可关闭双方剔除后比较。

剔除采用包围体，因此会保留一些实际上没有像素落入画面的对象；它不会做遮挡剔除。标准场景使用正缩放和不透明材质。

负缩放的朝向由世界矩阵左上 3×3 的行列式决定，包含父节点变换。行列式以 f64 求值，避免有限 f32 缩放在乘积中溢出或下溢。小于零时使用 CW，否则使用 CCW；零行列式不标记为镜像。逐对象路径只切换正面状态，仍保留描述顺序。实例化路径在每个资源组内先存 CCW 矩阵，再存 CW 矩阵，每个可见对象只上传一次。

`batch_counts()` 仍返回各资源组的可见对象总数；`batch_count()` 返回非空朝向批次数，同一资源组最多贡献两次实例化绘制。

每帧扫描所有可绘制节点，复杂度 O(M + B)。矩阵空间和组游标预分配，准备队列时不重新分配这些缓冲。

### 世界 AABB 查询

`SceneGraph.world_aabbs(nodes, local_bounds)` 批量将局部轴对齐盒转换为世界轴对齐盒，每项为 min xyz / max xyz。它读取已更新的世界矩阵，与渲染队列的包围球独立；调用方负责提供覆盖局部几何的盒。查询不修改场景版本或准备好的队列，重复节点合法，结果按输入顺序返回独立副本。

对每个世界坐标轴，根据矩阵系数正负选择局部各轴的最小、最大贡献，再加平移。有限 f32 的乘积可在 f64 中精确表示；累加时恢复加法的舍入误差方向，必要时向外扩展 f64 端点，最后再次向外舍入到 f32。该区间运算避免包围范围因舍入缩小，包含负缩放和层级剪切。身份变换下的零尺寸盒及 f32 最大端点保持原值。

输入、节点和场景有效性先校验；任一结果不能用有限 f32 保守表示时整批报错，错误包含查询编号。复杂度 O(Q)，输出为 6Q 个 f32。它不是紧致有向盒，也不保证大数抵消时仍足够紧；输出只相对于已经存储的世界矩阵保守，不提升 GPU 顶点投影精度。

### 射线与包围盒

`ray_aabb_intervals(origin, direction, world_bounds, t_min, t_max)` 是独立的 Rust 批量接口，最多处理 100,000 个世界 AABB。射线保持输入的参数形式 `origin + t × direction`，不归一化方向；返回每个盒的进入/离开参数，未命中使用 `[-1, -1]`。输出为独立的 f64 数组，顺序与输入盒一致。它只筛选候选，BVH 尚未实现。

逐轴求解射线在盒内的参数区间，再与用户区间求交。方向分量为正零或负零时直接检查起点是否落在该轴范围内，避免边界上的 `0 × Infinity`；只有三个方向分量全部为零才拒绝。减法沿用向外舍入的 f64 累加，除法结果再向外扩展一个 f64 步长，减少相切和极端量级下的漏候选。有限 f32 坐标和非零方向的比值不会超过 f64 范围，输出不缩回 f32。

参数必须满足有限 `t_min ≥ 0`、`t_max ≥ t_min`，正 Infinity 只可作为上限。表面接触算候选，盒内起点返回裁剪后的起始参数。输入完整校验后才开始求交，错误不返回部分结果；复杂度 O(Q)，不修改场景、队列或 GPU 资源。世界盒是快照，变换或几何更新后由调用方重新查询。

### 射线与三角形

`ray_triangle_hits()` 接收一条射线、有限 xyz 顶点和三角形索引，与包围盒接口共用射线及参数范围校验。每个三角形输出 `[t, weight_a, weight_b, weight_c]`，未命中为 `[-1, 0, 0, 0]`。顶点、射线先转成 f64，再通过边向量的叉积、点积求解射线参数与重心坐标；不使用绝对 epsilon 忽略极小三角形。索引顺序定义正面，可显式选择双面或背面剔除。

查询不修改输入、场景版本或渲染资源。输出与索引三元组一一对应，可用最小有效 t 查找最近三角形，再按三个顶点权重计算交点。顶点和射线需在同一坐标系；局部/世界转换和对象 ID 映射由调用方负责，镜像后的绕序也由调用方处理。

复杂度 O(V + T)，输出 4T 个 f64，最多 100,000 个三角形。零面积、平行或共面射线不返回唯一交点；共享边可能同时命中相邻三角形。此实现是浮点求交，不提供精确谓词或任意共享边下的 watertight 保证；细长三角形、近乎平行射线和严重抵消仍受舍入影响。BVH、场景级拾取与误差边界仍需后续完善。

## 渲染资源

EngineRenderer 构造时选择逐对象或实例化模式。两者共用几何体/材质注册，但使用不同顶点 shader。逐对象模式不创建实例 buffer，也不配置实例属性，只更新 modelMatrix uniform 并调用普通 drawElements。几何体和材质不变时复用绑定状态。

实例化模式管理一个动态矩阵 buffer，每个几何体 VAO 引用这个 buffer，切换组时更新矩阵属性偏移。

构造时会检查实例矩阵缓冲的实际字节数，创建了句柄但未取得请求容量也视为分配失败，释放缓冲和 program 后返回错误。旧 RustRenderer 同样检查顶点、索引、矩阵和颜色四个缓冲，上传前就建立统一的资源所有权，任一步失败都会释放已创建的句柄。零实例的零字节缓冲仍是合法输入。上下文恢复时沿用这些检查，失败后保持 failed 状态并阻止绘制，不会误报恢复成功。

三个基础几何体由 TS 独立生成，Rust 接受一般索引三角形数组。材质目前只有 RGB 和 unlit 开关；其余使用共享 GLSL 的简单面光照。所有材质均不透明。

面法线通过片元导数计算。顶点 shader 将 `mat3(modelMatrix) * position` 传给片元阶段，保留旋转、缩放和剪切，去掉不影响法线的平移。直接对很大的世界坐标求导会丢失小的表面起伏，这个相对坐标避免了该问题。两个导数分别按最大绝对分量缩放后再叉乘，防止极大或极小缩放使法线归一化溢出；零长度法线使用环境亮度，unlit 材质直接输出基础颜色。

Rust 与 Three.js 对照仍使用相同 shader，旧实验页也采用同样的法线处理。顶点投影和深度计算仍走 f32 世界坐标，因此该修改不提供完整的大世界坐标精度，也不会恢复已经在几何顶点中丢失的细节。

`add_geometry()` 和 `add_material()` 返回注册 ID。`set_batches()` 设定队列组到资源 ID 的映射。`render(queue, viewProjection)` 只提交绘制，不会自动更新场景或队列。

`EngineRenderer.update_geometry(id, positions)` 只更新已有顶点缓冲，顶点数量和索引不变。输入校验在上传之前完成；使用 bufferSubData，不新建 buffer、VAO 或 program。底层调用方需要同步更新包围体，可用 `geometryBounds()` 计算局部球，再调用 `queue.set_group_bounds(groupIds, center, radius)`，重新准备队列后绘制。

`Engine.updateGeometry()` 封装顶点更新与包围体同步：复制输入、计算包围球、上传顶点，再更新所有引用该几何体的组并使旧队列失效。新球心取局部 AABB 中心，先写为 f32，再计算覆盖全部顶点的半径并向外舍入，避免球心舍入或半径舍入缩小包围体。受影响组的自定义包围球会被替换，其他组保持原值。基础几何体的原点半径也采用向外舍入。

几何顶点、索引及批次映射在构造时复制保存；外部数组修改不会改变恢复后的几何。上下文丢失期间，SDK 只更新 CPU 顶点和包围球，恢复时重建最新几何。节点或资源数量变化仍需重建 Engine，几何卸载暂未实现。

顶点数量或索引变化使用 `Engine.replaceGeometry(id, positions, indices)`。它校验并复制全部输入，在 Rust 创建新几何成功后才提交 CPU 描述和受影响组的包围球，几何体 ID、批次映射和场景图保持不变。恢复流程读取最新顶点和索引，随后 `updateGeometry()` 以新的顶点数量为准。

底层 `EngineRenderer.replace_geometry()` 与新增几何体共用资源创建路径：预先创建 VAO 和两个缓冲，上传后检查实际缓冲字节数，再替换注册项并释放旧几何。任一步分配失败都释放临时句柄，原几何可继续绘制。新旧资源会短暂共存，因此峰值显存高于固定拓扑更新；这不是可变容量缓冲池。底层调用方仍需手动更新包围体并重新准备队列，SDK 会处理这一步。

`EngineRenderer.update_material(id, color, unlit)` 替换已有材质的颜色和光照开关。ID 和批次引用保持不变，参数校验通过后才写入；下一次绘制读取新值，不分配 shader、VAO 或缓冲。它不改变几何或可见性，因此不需要重新准备队列。

TS 的 `Engine.updateMaterial()` 保存同样的 CPU 材质状态。构造时复制材质参数，外部修改原 `EngineScene.materials` 不会在上下文恢复时悄悄改变材质；更新也不会回写调用方的数据或持有颜色数组引用。上下文可用时同步更新 Rust 注册表，丢失期间只更新 CPU 描述，恢复时从最新描述重建。此接口暂不支持纹理、透明度、增删材质或更换批次映射。

逐对象路径调用 `queue.prepare_direct(scene, viewProjection, culling)`，再调用 `renderer.render_direct(queue, scene, viewProjection)`。它不压紧或上传实例矩阵。两条绘制接口会检查队列和渲染器的模式，拒绝混用。

调用顺序是“修改场景 → 更新世界矩阵 → 准备队列 → 绘制”。更新失败后，即使捕获了异常，也不能继续使用之前的打包矩阵。两条 EngineRenderer 路径在清屏、上传和绘制之前检查队列状态；旧实验页的 RustRenderer 直接检查场景状态。保留的 `world_matrices()` 副本只代表读取时的数据，借用的 WASM 视图仅用于读取，不能绕过接口修改内部矩阵。

Renderer、Queue、SceneGraph 都有 `free()`。TS 的 Engine 用 `dispose()` 一起释放，重复 dispose 不会重复释放。资源数量变化时重建 Engine；单个资源卸载和动态节点增删暂未实现。更新材质、顶点或替换已有几何体的拓扑都不需要重建 Engine。

`EngineRenderer.resource_stats()` 返回独立的 `RendererResources` 快照。顶点和索引字节数来自注册表中已通过分配校验的几何，实例字节数按构造容量乘以 64；累加使用 f64，避免 wasm32 的 usize 总和溢出。统计不绑定缓冲，也不调用 `getBufferParameter`。零容量实例缓冲仍是一个 GPU 对象，虽然字节数为零。

底层快照是 WASM 对象，读取后需调用其 `free()`；它不引用渲染器，渲染器修改或释放后仍保留采样值。`Engine.resourceStats()` 负责转换成普通 TS 对象并立即释放底层快照，类型为 `GpuResourceStats`。上下文丢失时报告零 GPU 资源，CPU 场景数据仍保留用于恢复；直接使用底层渲染器时，调用方仍需负责释放旧实例并重建。该统计不包含浏览器和驱动分配，也不代表进程内存或真实显存占用。

`Engine.cpuResourceStats()` 是普通 TS 快照，统计引擎为重建而保留的顶点、索引、批次和动画 TypedArray 字节数。构造时这些数组会复制，之后 Engine 不持有完整 `EngineScene`；丢失/失败期间数值不变，`dispose()` 清空这些引用并返回零。它不统计 JS 对象与字符串、WASM `SceneGraph`/`RenderQueue` 的分配、浏览器 GC 或调用方仍持有的输入，因此不能作为堆、显存或加载峰值指标。

### 上下文丢失与恢复

`ContextLifecycle` 提供只读的 `state`、`generation` 和 `error`，状态为 ready / lost / failed / disposed。Engine 会阻止浏览器放弃恢复，在丢失事件中释放旧 GPU 句柄；收到恢复事件后从场景资源描述重新注册几何体、材质和批次。CPU 侧场景图、已修改的 TRS 和队列继续复用，不重新生成场景。

三个边界需要单独处理：丢失事件晚于 `isContextLost()` 的状态变化时，渲染入口也会拒绝绘制；恢复时资源创建失败则进入 failed；dispose 会移除事件监听，避免已释放的引擎被后续事件重新创建。

恢复回调执行期间忽略同步重入的恢复事件，避免重复重建。回调中调用 `ContextLifecycle.dispose()` 后，disposed 状态不会被正常返回或异常覆盖，也不会再通知 ready；未释放的实例在回调失败后仍可等待下一次上下文恢复。重建回调按同步接口执行，防护不负责取消调用方自行启动的异步任务。生命周期管理器只维护状态与监听，资源释放仍由所有者负责，Engine 使用 `dispose()` 统一释放。

对照页在任一后端失效时暂停双方，直到全部可用才继续。Three.js 自身会重建内部 GL 状态，适配器另外恢复用户设置的清屏颜色。浏览器是否以及何时恢复上下文不由引擎保证。

相关接口见 [WebGL 上下文丢失规范](https://registry.khronos.org/webgl/specs/latest/1.0/#5.15.2) 和 [Three.js r186 WebGLRenderer](https://github.com/mrdoob/three.js/blob/r186/src/renderers/WebGLRenderer.js)。

渲染队列每次准备前清空上一轮可见列表并标为无效。输入校验失败时，不允许渲染器继续提交旧列表；下一次有效准备可恢复正常工作。

## 相机和对照组

OrbitCamera 独立生成 look-at 和透视矩阵。两边从同一份 Float32 相机矩阵绘制；Three.js 只在自己的适配器中接收这些矩阵。三种基础几何体的顶点、索引、局部包围球也共用相同输入。

相机的矩阵乘法用 JS Number 累加四项乘积，完成一个元素后才写入 Float32Array，避免逐项写入时丢失抵消后的偏移或提前溢出。输入必须是 16 个有限值，最终结果超出 f32 范围时抛错，不返回含 Infinity 的相机矩阵。输入、输出及 GPU 计算仍为 f32；这项改动不解决全部大坐标投影或深度精度问题。

普通组用真正的 Three.js Mesh，矩阵自动更新开启，对象排序关闭。每个 Mesh 的 boundingSphere 使用场景提供的球心与半径，交由 Three.js 内部 Frustum 转换和检查；实例化适配器也读取同一组输入。Rust 逐对象组强制全量更新；预设场景的描述顺序与 Three.js 层级遍历的 Mesh 顺序一致。剔除默认关闭，每个对象在两边都对应一次绘制，可选同时开启球剔除。

优化组用 Object3D 保存层级，关闭自动局部矩阵重算，只标记动画节点，然后通过 Three.js 更新世界矩阵。它用 Frustum/Sphere 检查对象，将矩阵写入按几何、材质和朝向组织的 InstancedMesh，只标记有效的矩阵上传范围。普通 Mesh 由 Three.js 处理负缩放；实例化适配器给负行列式组使用 BackSide 材质，令 WebGL 正面切换为 CW，两边均保持背面剔除。该处理针对本项目共享的 RawShaderMaterial，不代表原生 InstancedMesh 的所有材质都支持负缩放。

Three.js 适配器为两种朝向各预留组内最大对象数的矩阵空间，以允许运行中改变缩放符号；每帧只上传可见范围。Rust 使用一个共享矩阵 buffer，总容量仍为对象数。两边绘制的批次、对象和三角形数相同，但缓冲分配方式不同。

只比较策略相同的一对：逐对象 Rust 对普通 Three.js，实例化 Rust 对实例化 Three.js。两者仍有 f32/Number、数据结构和框架开销差异，页面不把结果解释成纯语言速度。

## 测量

实时预览同时跑当前的一对实现。正式基准暂停预览，以 AB、BA、AB、BA 跑四轮，每组使用相同时间序列和冻结相机。提交结果前核对可见对象及三角形数；逐对象模式还检查 draw call 与可见数相等。不匹配的结果不导出。

CPU 从动画/矩阵更新前开始，到绘制提交后结束。准备阶段包括剔除和打包；普通 Three.js 的剔除发生在 render 内，所以在提交阶段。矩阵和视图准备的分工也稍有不同，优先比较总 CPU。

帧间隔采用相邻 rAF 时间戳，包含浏览器调度、刷新率和呈现节奏，不等于纯 CPU 耗时。GPU 查询仅包围绘制提交；结果异步收集，没有 gl.finish。GPU 空闲气泡可能计入查询，无法将它理解成纯光栅化用时。

计时扩展不存在时输出 null；遇到 disjoint 时清空该组 GPU 样本。等待查询结果最多额外经过 8 个 rAF，超时的查询删除，不阻塞 CPU。后台标签页、取消或画布尺寸变化会终止采样。

GPU 结果必须覆盖全部记录帧才计算中位数。队列达到上限、查询分配失败、结果超时或返回非法时长，都可能造成样本缺失；有部分有效结果时标记为 `incomplete`，中位数为 null。`gpuSamples` 保留已返回数据，`gpuExpectedSamples` 记录应有样本数，不能把部分样本的分布当作完整测试结果。零时长仍是有效返回值，但页面按计时分辨率显示“未分辨”；负数和非有限时长会被丢弃。

计时器拒绝重复 begin，dispose 会结束并释放未完成查询，之后不能重新启动。disjoint 会结束活动查询并释放待收集结果，整个计时器保持失效，不能因驱动标记清除而重新采集。

上下文丢失也会中止采样。每个异步帧边界后核对上下文代次，恢复再快也不接受跨代次结果。等待 rAF 支持 AbortSignal，因此标签页节流或暂停绘制期间也可以立即取消。GPU 查询一旦失效就丢弃，不在新上下文里访问旧查询。
